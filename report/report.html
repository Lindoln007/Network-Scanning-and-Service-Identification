1Executive summary

An isolated lab network of three hosts was scanned with Nmap to find active hosts, open ports and the services running on them. The scan found 3 active hosts and 13 open TCP ports running seven types of service. Eight findings were raised. Two are high risk and should be fixed straight away: a backdoored FTP server (vsftpd 2.3.4) and clear-text Telnet remote login.

2Objective and scope

Objective: use Nmap to scan an isolated laboratory network and identify active hosts, open ports and running services, then report the services found with security recommendations.

Scope: TCP scanning of 127.0.10.1–50 only. Exploitation of the services found and UDP scanning were outside the scope.

3Lab environment

A Python script (lab/lab_services.py) creates the lab by binding services to three addresses in the loopback range. Loopback traffic never leaves the computer, so the lab is fully isolated from any real network.

HostRoleServices configured
127.0.10.10Web serverSSH (OpenSSH 7.4), HTTP (Apache 2.4.29)

Each service answers with the banner the real software sends, and the web servers answer real HTTP requests. Nmap identifies them from these replies exactly as it would a production server. The scans, traffic and results are real; the software versions are emulated.

4Methodology

PhaseCommand
1. Host discoverynmap -sT -Pn -p 21-25,80,8080 --open 127.0.10.1-50
2. Port scannmap -sT -Pn -T5 -p 1-1024,3306,8080 127.0.10.10,20,30

FlagMeaning
-sTTCP connect scan: completes the handshake, needs no raw-packet privileges
-PnSkip ping discovery and treat targets as up (every loopback address answers pings)
--openShow only open ports, so a host counts as live only if it runs a service
-T5Fastest timing template, safe on a local link
-sV / -sCService version detection / default NSE scripts
-oN / -oXSave normal and XML output as evidence

Observations: closed ports show as filtered because Windows drops, rather than resets, connections to unused loopback ports. The quick discovery sweep missed ports 21 and 8080, which the full port scan found. This shows why one quick scan is not enough.

6Findings and risk ratings

Risk combines how severe the weakness is with how easily it can be reached.

F-01 · Backdoored FTP server (vsftpd 2.3.4)

High
127.0.10.20 · 21/tcp

This vsftpd release was tampered with in 2011 to include a backdoor (CVE-2011-2523). A username ending in :) opens a root shell on port 6200, and public exploits exist. FTP also sends credentials in clear text.

Recommendation: remove it, rebuild the host if it was ever exposed, and replace FTP with SFTP. If FTP must stay, use a current, verified build with FTPS and block port 6200.

F-02 · Telnet remote login in clear text

High
127.0.10.20 · 23/tcp

Telnet has no encryption: usernames, passwords and whole sessions can be read by anyone who can see the traffic. It is also a common target for brute-force bots.

Recommendation: disable and uninstall telnetd, use SSH with key-based authentication, and block 23/tcp.

F-03 · Outdated SSH server (OpenSSH 7.4)

Medium
127.0.10.10 · 22/tcp

Released in 2016, with known vulnerabilities including CVE-2018-15473 (username enumeration). The version is visible to anyone who connects.

Recommendation: update OpenSSH, disable password and root login, restrict SSH to an admin subnet, and add rate limiting or fail2ban.

F-04 · Outdated Apache 2.4.29, version disclosed, no HTTPS

Medium
127.0.10.10 · 80/tcp and 127.0.10.30 · 8080/tcp

Apache 2.4.29 (2017) is affected by many published CVEs, including CVE-2019-0211 (privilege escalation). The Server header reveals the exact version and OS, and the site is served over plain HTTP.

Recommendation: upgrade Apache, set ServerTokens Prod and ServerSignature Off, and serve over HTTPS (TLS 1.2+) with an HTTP→HTTPS redirect and HSTS.

F-05 · Admin web panel reachable on port 8080

Medium
127.0.10.30 · 8080/tcp

A management interface is reachable on the admin workstation, and Nmap's http-open-proxy script reported that it "might be redirecting requests". An open proxy could be abused to reach internal systems.

Recommendation: bind the panel to localhost, an admin VLAN or a VPN; require MFA; disable mod_proxy unless it is needed, then re-test.

F-06 · SMB and RPC listening on all interfaces

Medium
All hosts · 135/tcp, 445/tcp (Windows lab host)

SMB has a history of serious worms (for example EternalBlue / MS17-010). On the positive side, SMB2 message signing is enabled and required, which prevents relay attacks.

Recommendation: block 135, 139 and 445 inbound on untrusted firewall profiles, disable file sharing where it isn't needed, make sure SMBv1 is off, and keep Windows patched.

F-07 · SMTP banner reveals internal hostname

Low
127.0.10.20 · 25/tcp

The Postfix banner discloses mail.lab.local, which helps an attacker map the network. Open-relay behaviour was not tested.

Recommendation: set a generic smtpd_banner, test for an open relay with --script smtp-open-relay, and require STARTTLS and authentication.

F-08 · Workstation SSH discloses OS version

Low
127.0.10.30 · 22/tcp

OpenSSH 8.9p1 is a supported build, but the banner reveals the exact distribution and patch level, and a workstation rarely needs inbound SSH.

Recommendation: disable inbound SSH on workstations unless it is needed; otherwise use keys only and restrict source addresses.

7Security recommendations

  1. Remove vsftpd 2.3.4 and replace FTP with SFTP. (F-01)
  2. Disable Telnet; use SSH with key-based authentication. (F-02)
  3. Patch OpenSSH and Apache to current releases; disable SSH password and root login. (F-03, F-04)
  4. Hide version banners in Apache and Postfix. (F-04, F-07)
  5. Use HTTPS everywhere, with TLS 1.2+, redirects and HSTS. (F-04)
  6. Restrict management services (admin panel, SSH, SMB, RPC) to an admin network or VPN with the firewall. (F-05, F-06, F-08)
  7. Keep SMB signing required, disable SMBv1, and keep Windows patched. (F-06)
  8. Re-scan after fixing with the same commands to confirm the exposures are closed.

8Limitations

  • The lab services are lightweight emulations that reproduce real banners and HTTP responses, so the findings show what Nmap reports, not confirmed exploitability.
  • No exploitation was attempted, in line with the project scope.
  • Only TCP was scanned; UDP services were out of scope.

9Conclusion

Nmap found 3 active hosts and 13 open TCP ports running seven types of service on the isolated lab network. The two most serious exposures, the backdoored vsftpd 2.3.4 and clear-text Telnet, should be removed straight away. Most of the remaining risk comes from outdated software that announces its version and from management services reachable from anywhere. Running only the services you need, patching and hiding versions, and firewalling management ports would close nearly all of it. The raw Nmap output for every phase is in the scans/ folder of the project repository.
