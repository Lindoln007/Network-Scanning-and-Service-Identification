§ 02 Findings

Eight findings, rated

Risk combines how severe the weakness is with how easy it is to reach. Open a finding to see the scan evidence and the fix.

Show

  • Issue

    Version 2.3.4 of vsftpd is infamous. The official download was tampered with in 2011 to include a backdoor (CVE-2011-2523): a username ending in :) opens a root shell on port 6200. Public exploit modules exist. FTP also sends credentials in clear text.

    Recommendation

    • Remove vsftpd 2.3.4 immediately and rebuild the host if it was ever exposed.
    • Replace FTP with SFTP over SSH.
    • If FTP is unavoidable, run a current, verified vsftpd build with FTPS, and block port 6200.

    Evidence

    21/tcp   open  ftp     vsftpd 2.3.4

  • Issue

    Telnet gives a remote shell with no encryption. Anyone who can see the traffic can read usernames, passwords and the whole session. Telnet is also a favourite target for automated brute-force bots.

    Recommendation

    • Disable and uninstall the telnet daemon.
    • Use SSH with key-based authentication for remote administration.
    • Block 23/tcp at the host and network firewall.

    Evidence

    23/tcp   open  telnet  Linux telnetd

  • Issue

    OpenSSH 7.4 dates from December 2016 and has several known vulnerabilities, including CVE-2018-15473 (an attacker can tell which usernames exist). The exact version is visible to anyone who connects.

    Recommendation

    • Update OpenSSH to the current release from the OS vendor.
    • Disable password and root login; use keys only.
    • Limit SSH to an admin subnet and add fail2ban or rate limiting.

    Evidence

    22/tcp   open  ssh     OpenSSH 7.4 (protocol 2.0)

  • Issue

    Apache 2.4.29 was released in 2017 and is affected by many published CVEs, including CVE-2019-0211 (local privilege escalation to root). The Server header gives the exact version and OS, so an attacker can look up exploits instantly. The site is served over plain HTTP.

    Recommendation

    • Upgrade Apache to the current 2.4.x release.
    • Set ServerTokens Prod and ServerSignature Off to hide version details.
    • Serve over HTTPS (TLS 1.2+), redirect HTTP to HTTPS and add HSTS.

    Evidence

    80/tcp   open  http    Apache httpd 2.4.29 ((Ubuntu))
|_http-server-header: Apache/2.4.29 (Ubuntu)
|_http-title: Lab Server

  • Issue

    A management interface runs on 8080 of the admin workstation with the same outdated Apache. Nmap's http-open-proxy script also flagged that the server might relay requests. If confirmed, an open proxy could be abused to reach internal systems. Moving a service to a non-standard port does not hide it.

    Recommendation

    • Bind the panel to localhost or an admin VLAN only, or put it behind a VPN.
    • Require strong authentication (MFA) for the panel.
    • Disable proxy modules (mod_proxy) unless they are needed, and re-test with --script http-open-proxy.

    Evidence

    8080/tcp open  http    Apache httpd 2.4.29 ((Ubuntu))
|_http-open-proxy: Proxy might be redirecting requests

  • Issue

    Ports 135 (RPC) and 445 (SMB) appeared on every lab address because the Windows host running the lab binds them to all interfaces. SMB has a long history of serious worms (for example EternalBlue / MS17-010). Good news: SMB2 message signing is enabled and required, which blocks relay attacks.

    Recommendation

    • Block 135, 139 and 445 inbound in Windows Defender Firewall on public and untrusted profiles.
    • Turn off file sharing where it isn't needed; make sure SMBv1 is disabled.
    • Keep signing required, and keep Windows fully patched.

    Evidence

    135/tcp  open  msrpc         Microsoft Windows RPC
445/tcp  open  microsoft-ds?
| smb2-security-mode:
|   2.02:
|_    Message signing enabled and required

  • Issue

    The Postfix banner announces the internal hostname mail.lab.local, which helps an attacker map the network. Open-relay behaviour was not tested in this scope.

    Recommendation

    • Set a generic smtpd_banner.
    • Confirm the server is not an open relay (nmap --script smtp-open-relay).
    • Require STARTTLS and authentication for submission.

    Evidence

    25/tcp   open  smtp    Postfix smtpd
Service Info: Host:  mail.lab.local

  • Issue

    OpenSSH 8.9p1 is a supported Ubuntu 22.04 build, a much better state than F-03. The banner still reveals the exact distribution and patch level, and a workstation rarely needs to accept inbound SSH at all.

    Recommendation

    • Disable inbound SSH on workstations unless it is needed.
    • Otherwise use keys only, apply security updates and restrict source addresses.

    Evidence

    22/tcp   open  ssh     OpenSSH 8.9p1 Ubuntu 3ubuntu0.1 (Ubuntu Linux; protocol 2.0)
§ 03 Conclusion

Summary

Nmap identified 3 active hosts and 13 open TCP ports running seven types of service. Two exposures are high risk and should be removed now: the backdoored vsftpd 2.3.4 and clear-text Telnet. Most of the remaining risk comes from outdated software announcing its version, and management services reachable from anywhere.

Three habits would close almost all of it: run only the services you need, keep what remains patched and quiet about its version, and firewall management ports to an admin network. After fixing, re-run the same scans to confirm.

Limitations: the lab services are lightweight emulations that reproduce real banners and HTTP responses, so the findings show what Nmap reports, not confirmed exploitability. No exploitation was attempted, in line with the project scope.
